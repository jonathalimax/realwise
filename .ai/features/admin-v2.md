# Admin v2, account management and support (contract)

Goal: make the admin a real operations console for an AI-first product, and give users self-service for account, plan, contact and deletion.
All admin endpoints live under `/admin/*` and use the existing `AdminGuard` (role `admin`). Pagination: `?page=1&pageSize=25` returns `{ items, total, page, pageSize }`. Dates are ISO strings. Money in the API is **USD for AI cost** (`costUsd`) and **BRL cents** for revenue (`*Cents`). Every mutating admin action calls `AdminAuditService.record()` (global, `apps/api/src/admin-common`).

## Area A: user-facing API (SupportModule, AccountModule, billing)
- `GET /support/config` (public) -> `{ whatsapp: string, email: string }` from env `SUPPORT_WHATSAPP` (digits, default `5541992310339`) and `SUPPORT_EMAIL` (default `suporte@realwise.com.br`).
- `POST /support/messages` (public, but uses the session user when logged in) body `{ message, name?, email?, subject? }`: validates (message 5..4000 chars, email required when anonymous), stores a `support_messages` row (`source` app|login), emails `SUPPORT_EMAIL` with Reply-To = the user's email (via NotificationsService), returns `{ ok: true }`. Simple per-IP/per-user rate limit (e.g. 5 per hour, in memory).
- `DELETE /account` (JWT, `@AllowWithoutSubscription`) body `{ confirm: 'EXCLUIR' }`: cancels any active Stripe subscription immediately (skip if Stripe unconfigured), permanently deletes ALL rows of the user across every table that references the user (discover tables with a `user_id` column; delete in FK-safe order with retry passes inside a transaction), then the user row, clears auth cookies, returns `{ ok: true }`. Reuse this as `AccountDeletionService.deleteUser(userId)` so admin can call it. Never allow deleting the owner/admin account through this endpoint (403).
- Billing self-service in `BillingModule` (all `@AllowWithoutSubscription`): `POST /billing/change-plan` `{ plan: 'monthly'|'annual' }` (updates the Stripe subscription item to the matching price, proration on), `POST /billing/cancel` (cancel_at_period_end = true), `POST /billing/resume` (cancel_at_period_end = false), and extend `GET /billing/status` with `amountCents`, `currency`, `nextPlanOptions`. State must end up correct through the existing webhook sync, but also update the user row optimistically from the Stripe response. Reject with 409 for lifetime/owner/no live subscription. Keep the fake Stripe used by E2E working.

## Area B: admin API for users, AI logs, analytics (AdminUsersModule, AdminLlmModule, AdminAnalyticsModule)
Users:
- `GET /admin/users?search=&state=trial|subscribed|lifetime|blocked|owner&sort=createdAt|lastActiveAt|aiCost&order=&page&pageSize` -> items `{ id, email, name, createdAt, lastActiveAt, access: AccessInfo-like { state, plan, trialEndsAt }, aiCostMonthUsd, transactionCount, reminderEmailsOptOut, marketingEmailsOptOut, adminNote }`. Search matches email/name (ILIKE).
- `GET /admin/users/:id` -> the same plus counts (accounts, transactions, imports, chat messages), last 20 LLM calls, support messages, subscription fields (Stripe ids, status, period end), audit entries for this user.
- `PATCH /admin/users/:id` `{ name?, email?, adminNote?, reminderEmailsOptOut?, marketingEmailsOptOut?, llmBudgetOverrideUsd? (number|null) }`.
- `POST /admin/users/:id/plan` `{ action: 'extend_trial', days } | { action: 'grant_lifetime' } | { action: 'start_trial', days } | { action: 'revoke' }`. `extend_trial`/`start_trial` set `premium_status='trialing'` and `premium_access_ends_at` (now+days, or end+days if still running); `grant_lifetime` sets `premium_status='active'` with no Stripe subscription (state `lifetime`); `revoke` ends access now (`premium_status='expired'`, ends_at=now) unless a live Stripe subscription exists (then 409 with a clear message). Use `computeAccess` from `billing/access.ts` to report the new state.
- `DELETE /admin/users/:id` -> `AccountDeletionService` (from area A; if not yet available, expose through an injected interface and note it). Refuse for admin/owner.
- All the above audited.
AI logs (`llm_call_log`):
- `GET /admin/llm-logs?userEmail=&userId=&model=&purpose=&status=ok|error&from=&to=&minCostUsd=&q=&page&pageSize` -> items `{ id, createdAt, userId, userEmail, purpose, provider, model, inputTokens, outputTokens, cachedInputTokens?, costUsd, latencyMs, error }` (`q` searches the error text and model). Cost in the table is `cost_micro_cents` (1e-8 USD).
- `GET /admin/llm-logs/summary?from=&to=` -> `{ totalCostUsd, calls, errors, errorRate, avgLatencyMs, p95LatencyMs, byModel:[{model,calls,costUsd,inputTokens,outputTokens}], byPurpose:[...], byDay:[{date,calls,costUsd,errors}], topUsers:[{userId,email,calls,costUsd}] }`.
- `GET /admin/llm-logs/export.csv` same filters.
Analytics (`GET /admin/analytics/overview?days=30`): `{ users:{total,new,dau,wau,mau,blocked,trial,subscribed,lifetime}, funnel:{signups,activated(first import or chat message),trialing,converted,expired,conversionRate}, revenue:{activeSubscriptions,monthly,annual,mrrCents,arrCents}, ai:{costUsd,calls,costPerActiveUserUsd,errorRate,byModel[]}, usage:{imports,transactionsCreated,chatMessages}, series:{signups:[{date,count}], activeUsers:[{date,count}], aiCostUsd:[{date,costUsd}]}, health:{llmErrorRateLast24h,llmCallsLast24h} }`. `GET /admin/analytics/users-usage?sort=cost|messages|imports&limit=` top users. Active = `last_active_at` or chat message/transaction activity. Also add a throttled `last_active_at` touch (at most once per 10 min per user) in the JWT auth path or a global interceptor.
- `GET /admin/audit?actor=&action=&targetUserId=&page` -> audit rows.

## Area C: admin API for communication and runtime settings (AdminCommsModule)
- Runtime settings via `AppSettingsService` (`get(key)`, `set(key,value,by)`, 60s in-memory cache, env fallback): keys `ai` `{ monthlyBudgetUsd, trialBudgetUsd, hardCapMultiplier, modelChat, modelChatLight, modelInsights, modelFallback, promptCache:boolean }`, `emails` (below), `announcement` `{ enabled, text, level:'info'|'warning'|'promo', linkLabel?, linkUrl?, until? }`. `LlmService` and `OpenRouterProvider` must read the `ai` settings (DB value > env > default) and honour `users.llm_budget_override_usd` first (for both trial and paid). `GET/PUT /admin/settings/ai`.
- Emails: `GET/PUT /admin/settings/emails` `{ engagement: { enabled, hourBrt (0-23), kinds: { trial_import:{enabled}, trial_ending:{enabled}, trial_expired:{enabled}, monthly_import:{enabled} } }, billReminders: { enabled, hourBrt } }`. Replace the fixed `@Cron` schedules of `EngagementRemindersScheduler` and `BillRemindersScheduler` with an hourly cron that runs the job only when the configured hour matches (America/Sao_Paulo) and the group is enabled; respect per-kind toggles in `EngagementRemindersService`. `POST /admin/emails/run-now` `{ job:'engagement'|'bills' }`, `POST /admin/settings/emails/test` `{ kind, to }` (sends a sample), `GET /admin/emails/sent?kind=&email=&page` from `reminder_emails_sent` joined with users.
- Support inbox: `GET /admin/support?status=&q=&page`, `GET /admin/support/:id`, `POST /admin/support/:id/reply` `{ message }` (emails the user from `SUPPORT_EMAIL`, stores reply, status `answered`), `PATCH /admin/support/:id` `{ status: 'open'|'answered'|'closed' }`. Also `GET /admin/support/stats` -> open count (for a sidebar badge).
- Campaigns (email marketing): `GET/POST /admin/campaigns`, `GET/PATCH/DELETE /admin/campaigns/:id` (only while draft), `POST /admin/campaigns/audience` `{ segment }` -> `{ count, sample:[{email,name}] }` (segment semantics in the schema comment; always excludes `marketing_emails_opt_out`), `POST /admin/campaigns/:id/test` `{ to }`, `POST /admin/campaigns/:id/send` (batched, ~10/s, records `email_campaign_sends`, updates counters, idempotent per user, status sending->sent; optional `scheduledAt` handled by an hourly check). Emails use the brand template and always include a one-click unsubscribe link: public `GET /marketing/unsubscribe?u=&t=` (HMAC like the reminder one, sets `marketing_emails_opt_out`). `GET /admin/campaigns/:id/sends`.
- Announcement banner: `GET /announcement` (public/JWT-free) -> current enabled, non-expired announcement or `null`; managed through `PUT /admin/settings/announcement`.

## Area B implementation notes (users, AI logs, analytics)
- Shared helpers: `admin-common/admin-query.util.ts` (paging max 100, safe date parsing, CSV cell escaping) and `admin-common/access-sql.ts` (SQL mirror of `computeAccess` to filter/count by access state in the database; keep in sync).
- Dates: `YYYY-MM-DD` filters are Brazil-time days (`to` inclusive of that day); daily series are bucketed in `America/Sao_Paulo`. Ranges are capped (llm logs 400 days, overview `days` 1..365). Rates (`errorRate`, `conversionRate`) are fractions 0..1.
- PATCH email, plan and delete refuse admin/owner users (403). Plan: `extend_trial` adds to a running trial, `start_trial` always restarts from now; trial actions 409 on lifetime or live-subscription users; `grant_lifetime` and `revoke` 409 while a Stripe subscription is live (revoke also inside a paid period). Plan response: `{ id, access }`.
- `DELETE /admin/users/:id` uses the `ACCOUNT_DELETION` token (`admin-users/account-deletion.token.ts`); Area A must provide it or the endpoint answers 503.
- `users.last_active_at` is stamped by the global `LastActiveInterceptor` (admin-analytics), at most once per 10 minutes per user (in-memory throttle plus conditional UPDATE). DAU/WAU/MAU read it; `series.activeUsers` uses chat messages, imports and the last-active day.
- MRR uses list prices 899 / 7490 cents (override `ADMIN_PRICE_MONTHLY_CENTS` / `ADMIN_PRICE_ANNUAL_CENTS`); promotion-code discounts are not reflected.
